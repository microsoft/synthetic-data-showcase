# Security Review Report
**Date**: 2026-08-31 18:45:14
**Scope**: `scan-91983a14-cfc5-45bc-9a55-a04e554e52da-report/`, deployed GitHub Pages assets, and the pending dependency/workflow remediation

## Findings

### Vulnerable DOMPurify remains deployed
**File**: `packages/webapp/package.json` (line 40); deployed `assets/main-6eb3ce9b.js`
**Severity**: Medium
**Issue**: The live bundle contains DOMPurify 3.0.1 and triggers multiple sanitizer-bypass advisories, although the pending source change upgrades it to 3.4.14.
**Impact**: The vulnerable component could permit XSS if attacker-controlled markup reached the sanitizer. Current application usage only processes bundled tooltip Markdown, so no exploitable input path was identified.
**Remediation**: Deploy the locally verified 3.4.14 build. The finding remains open until the GitHub Pages bundle is replaced.

### Vulnerable lodash remains bundled
**File**: `packages/webapp/package.json` (line 42); `yarn.lock` (lodash resolution); deployed `assets/SdsManager-7b759873.js`
**Severity**: Medium
**Issue**: The deployed bundle contains lodash 4.17.21, which is affected by the three advisories reported by ZAP. The pending source change upgrades lodash and lodash-es to 4.18.1.
**Impact**: The advisories affect `template`, `unset`, and `omit`. No first-party use of those APIs was found, so the vulnerable code is present but no practical exploit path was demonstrated.
**Remediation**: Deploy the locally verified 4.18.1 build. Lint, tests, and the production build pass, and the rebuilt bundles contain 4.18.1 with no 4.17.21 signature.

### Browser hardening headers are unavailable
**File**: `packages/webapp/index.html` (lines 3-8); deployed root response
**Severity**: Low
**Issue**: The root response lacks Content-Security-Policy, X-Frame-Options, and X-Content-Type-Options.
**Impact**: This removes defense-in-depth against future XSS, framing, and MIME-sniffing issues. Current risk is limited because the site is a public static SPA without authenticated or state-changing operations.
**Remediation**: Accept and document the GitHub Pages platform limitation, or move to hosting that supports custom response headers. A CSP meta element can partially mitigate script/content injection, but cannot enforce `frame-ancestors` or replace X-Frame-Options.
